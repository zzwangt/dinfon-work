# 鼎峰 · 项目管理平台 v2

以项目流程为中心的内部协作平台：大节点表示阶段或周目标，小节点表示任务，连接计划、成果提交、验收、延期审批与管理汇总。

当前版本采用 **Vinext / Sites + Cloudflare D1**。发布站点使用各自的 ChatGPT 登录身份，业务数据和权限由服务器管理；已移除浏览器内的演示身份切换。当前仅站点所有者已开通管理员账号，其余初始化人员和项目仍为业务示例，不代表员工已真实注册或参与。

## 账号开通与访问

站点目前保持私有访问。员工进入平台需要同时满足两项条件：

1. 管理员在“账号管理”中登记员工实际使用的 ChatGPT 登录邮箱，分配角色；已有任务归属时选择“关联已有成员”。
2. 在 **Sites 站点共享设置**中，允许同一邮箱访问本站。

创建平台账号不会自动修改站点共享权限，也不会发送邀请。员工首次登录后，服务器将登记邮箱与托管层验证过的稳定用户身份绑定；邮箱或身份不匹配时拒绝进入。

| 角色 | 访问范围 |
| --- | --- |
| 管理员 `admin` | 全部业务数据、管理后台、人员统计、账号开通、角色调整、停用和延期审批 |
| 项目负责人 `manager` | 员工工作台及参与项目；可创建自己负责的项目，并管理所负责项目的节点、任务和延期申请 |
| 成员 `member` | 员工工作台及参与项目，处理自己负责的任务；被指定为验收人时可验收他人的任务 |

员工无权进入全局管理后台、账号管理、全员统计或平台设置。角色调整不会自动改变项目负责人和任务归属。停用账号后，下一次服务器请求即被拒绝；已加载到浏览器的内容不能远程撤回。项目成员资格被撤销后，也不能继续操作旧任务。

## 主要功能与规则

- **流程画布**：缩放、平移、节点详情，以及“全部任务 / 本周重点 / 我的任务”筛选。筛选保留完整阶段结构；已完成阶段的任务默认收起，可展开回看。
- **项目执行**：先创建大节点，再分配关联任务。任务有主负责人、验收人、截止日期和验收标准；提交成果并验收通过后才算完成。
- **每周工作**：本周必须完成的大节点包含此前遗留的未完成节点；逾期和受阻单独提示。周汇总按所选周截止日期统计，可导出报告。
- **延期审批**：项目负责人提交原因、新日期、后续安排及明确勾选的节点/任务调整。审批前和驳回后均保持现行计划；批准后统一调整所选日期，保留原始日期和历史记录。申请人不能审批自己的申请。
- **管理汇总**：项目进度、节点达成、任务验收、逾期、人员指标、延期和操作记录可下钻查看。

项目进度按“已验收节点权重 ÷ 全部节点权重”计算；仍有未完成节点时最高显示 99%，全部完成才显示 100%。节点必须有至少一项关联任务，且全部任务已验收，才能确认达成。

人员指标统一取所选周内截止的任务：计划完成率为已验收数量 / 计划任务数；按时提交率按最近一次成果提交的上海时间与当前批准截止日期比较；一次验收通过率为首次通过数 / 已发生首次验收数。当前周包含尚未到期任务，分母为零显示“—”。这些指标用于观察执行情况，不直接作为绩效排名。

## 本地开发

需要 **Node.js 22.13.0 或更高版本**及 npm。先在项目目录安装依赖：

```sh
npm run install:ci
```

本机开发服务使用 Sites 的**本地模拟登录**，不是发布站点的真实 ChatGPT 认证。仅在本机 `.dev.vars` 中配置模拟邮箱；不要在文档、公开文件或前端代码中填写真实管理员邮箱：

```dotenv
# 仅用于本机模拟登录，不可作为正式部署配置
FIRST_ADMIN_EMAIL=seedy@sites.test
```

全新本地数据库需先建表。已有本地数据库不要重复执行初始化 SQL：

```sh
npm run build
npx wrangler d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_amusing_cerebro.sql
```

启动开发服务：

```sh
npm run dev -- --port 4173
```

打开 [本地平台](http://localhost:4173)，或在依赖安装完成后双击 `启动平台.command`。本地模拟认证只供本机使用，不应通过局域网监听、端口转发或公网隧道向他人开放。正式站点由 Sites 托管认证层验证身份；本地模拟登录成功不能证明真实员工已能访问正式站点。

`npm start` 用于运行已经构建的本地 Worker，并非旧版 Python 静态服务器。不要直接打开 HTML 文件或使用 `serve.py` 启动 v2。

## 数据与部署

- 共享业务数据与账号绑定写入 D1。浏览器通过 `/api/session` 读取自己的可见数据，通过 `/api/command` 提交业务变更；账号接口仅供管理员使用。
- 写请求校验同源来源、登录身份和业务权限，并用 `revision` 做条件更新（CAS）。数据版本冲突时返回 409，刷新后重新提交，不覆盖别人的修改。
- API 的业务响应不会包含登录绑定记录、其他人的登录邮箱或认证标识。管理员账号列表使用单独的受限接口。
- 正式环境的 `FIRST_ADMIN_EMAIL` 必须由部署者在服务器配置为已核实的站点所有者邮箱。未配置或身份不匹配时不会自动授予首位访客管理员权限。
- 旧版 `localStorage` 数据仍留在原浏览器、原网址中，没有自动合并进 D1。管理员可在同一来源的“平台设置”导出旧版备份；新网址无法读取旧网址的浏览器数据。
- 可导出业务 JSON 和周报；目前没有备份导入、自动恢复、附件上传、邮件邀请或自动消息提醒。业务 JSON 不包含账号绑定，不能替代完整 D1 备份。

当前员工视图、权限隔离、禁用、身份绑定和并发冲突有服务器自动化测试覆盖；尚不能据此声称多个真实员工已完成端到端使用验证。员工试用还需要逐人完成站点共享授权与实际登录验收。

tests/                      领域、访问范围、流程图与服务器测试
.openai/hosting.json         Sites 数据库绑定声明
dist/                       构建产物，不是业务源码目录
```

npm test

```
